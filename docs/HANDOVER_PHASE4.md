# Smart Schedule 프로젝트 인수인계 문서 (HANDOVER 4 - 통계 시스템 Phase 준비)

## 1. 프로젝트 현재 상태
본 문서는 **Smart Schedule** 백엔드 개발의 3단계(알림 시스템) 및 자체 인증 시스템 구축이 완료된 시점에서 작성되었습니다. 실제 메일 발송 테스트까지 성공하였으며, 시스템 안정성이 확보된 상태입니다.

---

## 2. 완료된 작업 요약 (Phase 3 및 인증 리팩토링)

### 2.1. 이메일 알림 시스템 (Notification) 완성
- **MailService 구현**: `JavaMailSender`를 활용한 비동기(@Async) 이메일 전송 로직 구현. 네트워크 순단 현상 대비 **최대 3회 재시도(Retry)** 로직 적용 완료.
- **ScheduleNotificationService 구현**: `@Scheduled`를 통해 매 분마다 DB를 폴링하여 발송 대상 알림을 포착하고 처리하는 오케스트레이터 구현 완료.
- **안정성 확보**: 실제 운영 환경과 유사한 조건에서 이메일이 정상 수신됨을 확인.

### 2.2. 자체 인증 시스템 구축 및 DTO 기반 리팩토링
- **회원가입/로그인 확장**: 소셜 로그인 외에 이메일 기반의 자체 회원가입(`POST /api/v1/auth/signup`) 및 로그인 기능을 추가.
- **계층 간 격리 완성**: 서비스 계층(`MemberCommandService`, `MemberQueryService`)과 보안 계층(`CustomUserDetails`)에서 엔티티 노출을 완전히 차단하고 `MemberResultDTO`를 사용하도록 전면 리팩토링.
- **Converter 통합**: `MemberConverter`를 생성하여 엔티티와 DTO 간 변환 로직을 한곳에서 관리.

### 2.3. 테스트 환경 및 런타임 안정화
- **통합 테스트 성공**: `build.gradle`의 `test` 태스크를 수정하여 시스템 환경 변수 간섭 없이 H2 DB로 테스트가 수행되도록 격리 (`BUILD SUCCESSFUL`).
- **런타임 오류 해결**: `application.yaml`의 크론식 문법 오류(따옴표 누락) 및 환경 변수 우선순위 문제를 해결하여 `bootRun` 성공 확인.

---

## 3. 다음 세션 작업 예정 사항 (Phase 4 - 통계 대시보드)

다음 세션에서는 기획된 통계 API를 본격적으로 구현합니다.

### 3.1. 통계 조회 API 구현
- **일정 완료율**: 특정 기간 내 전체 일정 대비 `DONE` 상태 일정의 비율 산출.
- **카테고리별 분포**: 사용자의 카테고리별 일정 점유율 및 개수 집계.
- **주간 활동 추이**: 최근 4주간의 주차별 활동량(생성된 일정 수) 통계 데이터 제공.

### 3.2. 성능 최적화 및 안정화
- **집계 쿼리 최적화**: QueryDSL을 활용한 효율적인 통계 쿼리 작성.
- **캐싱 전략**: 변동성이 적은 과거 통계 데이터에 대해 `@Cacheable` 적용 검토.

---

## 4. 참고 사항
- 현재 `application.yaml`의 크론식은 `${NOTIFICATION_CRON:"0 * * * * *"}` 형태로 따옴표가 반드시 포함되어야 함을 유의하십시오.
- `MailService`의 재시도 지연 시간은 내부 변수(`retryDelayMillis`)로 관리되며, 테스트 시에는 리플렉션을 통해 0으로 조정되어 있습니다.
